# M4 — Four-arm experiment on the frozen test set

**Authority:** brief §1.6 (skill), §2.2 (arms), §2.4 (metrics, headline `grounded_accuracy`),
§2.7, §6 (acceptance 3, 7, 8), Appendix B (skill rules and adherence). **Spend-gated.**

## Deliverables

1. **Skill** — `skills/ma-deal-point-review/SKILL.md` (generic procedure, the 8 rules of Appendix
   B, ≤ ~800 tokens) + `playbooks/q01.md … q12.md` (3–5 lines each). `skill_version` = hash of the
   files, written to `versions.json`. Injected as a system-prompt block in **arm D only**; the
   applicable playbook is loaded only for the case's question.
2. **Skill adherence scorer** — each Appendix-B rule as a deterministic trajectory check with an
   *applicable* predicate; `skill_adherence` = satisfied / applicable; computed for **all arms**.
3. **Arms** — configs A/B/C/D exactly as brief §2.2; a test asserts each arm differs from its
   predecessor by exactly one config key.
4. **Frozen discriminative subset** — `data/eval/test_subset_v1.json`, chosen **before any test
   case runs and without looking at any model output**, by deterministic rule: from `test`, 2 cases
   per question (24) favouring the reasoning types where arms should differ — defined-term,
   cross-reference and carve-out questions get their cases first; ties broken by seed — plus 8
   `counterfactual` cases (6 redacted across ≥ 4 questions, 2 out-of-scope). 32 cases. The rule
   and the seed are in the file; a test regenerates it byte-for-byte. Sized so that 4 arms fit the
   M4 allocation at the constant model; if the ledger's measured cost/case says 32 does not fit,
   reduce to 1 case per question + 6 counterfactual (18) by the same rule and record it.
5. **Sweeps** — constant model **`anthropic/claude-haiku-4.5`** (the budget's strong default; a
   weaker model also makes retrieval and skill effects more visible): arms A–D on the frozen
   subset only. No dev sweep. Before the sweeps, `assert_within_cap` must pass and the projected
   cost is recorded. **No test run may be used to change any config, prompt, or skill; the skill,
   arm configs and the subset are frozen (hashes recorded) before the first test case runs.**
6. **Report** — `just report` → `data/reports/four_arm.json` (every §2.4 metric per arm, overall and
   per question, plus majority baseline, plus the config diff between adjacent arms, plus
   estimate-vs-realised cost) and `four_arm.md`; README "Results" section regenerated from it with
   the MAUD non-comparability caveat, the objective-vs-judged distinction, and the budget-scaled
   subset stated in the first sentence. Braintrust experiments for each arm, names recorded in
   `braintrust_runs.json`. With 32 cases, report **paired** per-case arm comparisons (which cases
   flipped between arms) — with small N that is the evidence, not aggregate percentages alone.

## Honesty rule
If arm D does not improve `grounded_accuracy` over C, the report says so and shows adherence,
fabrication, abstention, trajectory and efficiency deltas instead; no wording may claim an
improvement the numbers do not support (the reviewer checks the README sentences against the JSON).

## Definition of done

- [ ] `gate_m4` offline: adherence rules unit-tested (applicable/satisfied on synthetic
      trajectories); arm-diff test; report generator tested on fake results; skill files exist and
      `skill_version` is stamped.
- [ ] `test_subset_v1.json` frozen and regenerable; `four_arm.json` covers 4 arms on the subset;
      per-question tables, paired flips, majority baseline and estimate-vs-realised cost present;
      README results section regenerated by `just report` and consistent with the JSON (a test
      compares the numbers). M4 realised spend ≤ $1.50.
- [ ] Spend gate passed before sweeps; ledger totals for M4 recorded in the report.
- [ ] Full offline suite, `ruff`, `pyright` green.


## Budget scaling (engineer decision, 2026-09-04 — not a spec/brief contradiction)
The whole unattended OpenRouter envelope for M1–M6 is **$4.00** (`MAX_OPENROUTER_SPEND_USD`). Where this spec is smaller than the brief's full-scale design (§2.2, §2.5, §2.6), the scaling below is the engineer's instruction and must be recorded in the report as "budget-scaled", never presented as the full benchmark. Every metered run is sized by `dealpoint.eval.spend.estimate` from measured cost/case in the ledger, and the milestone's own runs must leave headroom for the milestones after it (allocation guide: M1+M2 ≤ $0.50, M4 ≤ $1.50, M5 ≤ $0.60, M6 the remainder).
