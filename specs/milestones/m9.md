# M9 (draft, awaiting hand-off): the MLflow mirror of the Braintrust showroom

**Authority:** `specs/grilled-product-brief.md` (§2.7: the observability product is a *surface*, never the
source of truth; the reports in Git decide), `specs/milestones/m7a.md` and `m7b.md` (namespaces, experiment
names, score budgets, the reproducibility contract), the Braintrust showroom as built on 2026-09-07
(`dealpoint/eval/braintrust_showroom.py`, `braintrust_cockpit.py`, `docs/demo-tour.md`), and the engineer's
directive of 2026-09-07: **have something similar in MLflow that takes as much as we have in Braintrust,
copied straight over, and uses as many of MLflow's relevant tools as our data supports.**

M9 is additive. Nothing from M1 to M8 is rerun, retuned or re-judged. Every MLflow object is built from
the same stored rows the Braintrust objects were built from, by one command, idempotently, into a
self-hosted open-source MLflow tracking server. Braintrust stays as it is.

Ordering: independent of M8 (M8 changes the agent; M9 changes only where the evidence is displayed).
Spend-gated only for the two MLflow-unique steps that call models (judge alignment, prompt optimization);
everything else is free.

## 1. Principles

1. **Same rows, same numbers, same names.** Every MLflow number equals the Braintrust number for the same
   (case, variant) because both come from the same stored row through the same pure function. A test asserts
   it for the spine case (`contract_144__q05`, D@glm) and the redacted twin.
2. **One command, dry run by default, idempotent.** `just mlflow-sync` prints the plan; `--live` writes;
   a second `--live` creates nothing new (search by deterministic tag `dealpoint.key`, then update).
3. **Nothing metered, still guarded.** MLflow has no score meter. The only spend is OpenRouter calls in the
   two MLflow-unique steps; each is its own flag (`--align-judges`, `--optimize-prompt`), prints its call
   count and dollar estimate before the first call, and is capped (§6).
4. **Free tier of the box.** The tracking server runs on this VM with SQLite; artifacts on disk under
   `data/mlflow/` (gitignored, like `data/index/`). Disk guard as in M7a (`dealpoint/eval/disk_guard.py`).
5. **The verdict travels.** The scoring definitions (safe accuracy, precision when answering, net accuracy,
   misleading, silent failure) and the per-question verdicts are written into the experiment description,
   the run descriptions and the registered model versions, in the same words as the Braintrust dashboards.
6. **Gaps are named, not papered over.** Monitoring, Topics, Patterns, Loop, Playground and labeling
   sessions are Databricks-only or absent; the walkthrough says so in one line each.

## 2. Deliverables

### D1. Tracking server and the `mlflow` extra

- `pyproject.toml`: optional extra `mlflow = ["mlflow>=3.16"]` (lazy import everywhere, same rule as
  `braintrust`, `deepeval`).
- `just mlflow-server`: `mlflow server --backend-store-uri sqlite:///data/mlflow/mlflow.db
  --artifacts-destination data/mlflow/artifacts --host 127.0.0.1 --port 5000`. `MLFLOW_TRACKING_URI`
  defaults to `http://127.0.0.1:5000`; tests use `sqlite:///<tmp>` directly (no server).
- The UI reaches the operator through the exe.dev HTTPS proxy (documented exe.dev features only; the
  operator wires it, the factory documents the port).

### D2. `dealpoint/eval/mlflow_mirror.py` and `just mlflow-sync`

Steps, each a function `step_<name>(client, live, manifest)`, `--only` to pick, run in this order:

| step | creates | from |
|---|---|---|

| `prompts` | 8 registered prompts (chat form where the Braintrust one is chat), versions, aliases `baseline` (arm-A base), `best` (cite-first), `judge-panel`, `rubric`, `skill` | `prompt_plan`, `playground_prompts`, `judge_run._system_prompt` |

Dry run prints counts per step and writes nothing. Live writes and records
`data/reports/mlflow_manifest.json` (ids, counts, tracking URI, MLflow version). Idempotency: tag
`dealpoint.key` on runs, traces (`dealpoint.key` = `case:variant:category`), datasets (name), prompts
(name + content hash -> no new version when unchanged), model versions (name + config hash).

### D3. `just mlflow-align-judges` (MLflow-unique, spend-gated)

`judge.align(traces)` for each of the four judges over the 24 lawyer-scored traces (HUMAN feedback as
the target), then re-score the 108 judged traces with the aligned judges and log `judge/<dim>/aligned`
assessments and a run `judge-alignment` whose metrics are closeness-to-lawyer before and after, per
dimension and per family (the same definition as `metadata_mirror`'s `judge_*_closeness`). Dry run prints
the call count; live requires `--live` and stops if the estimate exceeds the cap (§6). Result recorded in
`data/reports/judge_alignment.json` and one paragraph in the walkthrough: did alignment move the trajectory
dimension, the one no judge gets right?

### D4. `just mlflow-optimize-prompt` (MLflow-unique, spend-gated, optional)

`mlflow.genai.optimize_prompts` (GEPA) on `arm-a-prompt-base` over the 18 `playground-armA` rows with the
evidence judge as the objective, registered as a new prompt version with alias `optimized`, evaluated once
with the same judges as the four hand-written variants so the prompt comparison has a fifth row. Skipped
(not failed) when the cap would be exceeded or the extra is not installed.

### D5. `docs/mlflow-tour.md`

The nine stops of `docs/demo-tour.md`, one paragraph each, pointing at the MLflow surface for the same
evidence: dataset -> Datasets tab; retrieval -> the `retrieval` evaluation run and its comparison chart;
A to D -> Evaluations comparison of the four GLM runs, row `contract_144__q05`; trace -> Traces tab,
filter `tags.case_id = 'contract_144__q05'`, the span tree with real timestamps; scorers -> the six
in-process scorers and the four judges, plus `just mlflow-score-new`; judges and the lawyer -> assessment
columns on the Traces tab, the judge-alignment run; Playground -> the prompt registry versions and the
optimized prompt; failure investigation -> `search_traces` for `tags.status = 'CAP_HIT'` and the
redacted-twin trace (no Loop, no Topics, said plainly); economics -> the `Which model?` run comparison
and the registered model's `champion` alias. Plus a "What MLflow adds" section (in-process deterministic
scorers, real timestamps, judge alignment, prompt optimization, the model registry) and a "What only
Braintrust has here" section (monitor dashboards over logs, online scoring, Topics, Patterns, Loop,
Playground, labeling), one line each.

### D6. Tests and gate

Marker `gate_m9`, offline, no network: MLflow against a temporary SQLite tracking URI (`mlflow.set_tracking_uri`)
in a `tmp_path`, so the tests exercise the real client, not a fake. Required tests:

- every step's dry run reports the counts in §2 D2 exactly (35 runs, 9 datasets, 8 prompts, 739 traces,
  assessment counts: 986 x 6 CODE for obj, 108 x 4 x 3 LLM_JUDGE, 24 x 4 HUMAN, 108 x 4 CODE for DeepEval,
  406 x 3 CODE + 406 x 2 CODE for retrieval);
- `--live` into the temporary store creates those objects; a second `--live` creates nothing new (count
  runs, traces, dataset records, prompt versions before and after);
- the spine case and the redacted twin: every assessment value on the MLflow trace equals the
  `metadata_mirror` value from the same row (`ga_scored`, `net_accuracy`, `safe`, `judge_mistral_evidence`,
  `human_professional`, DeepEval task completion);
- each of the six deterministic scorers, called as an MLflow scorer on the spine trace, returns the
  stored row's value;
- the four judges are constructed with the OpenRouter base URL and the rubric dimension text, and never
  called in the offline suite;
- `align` and `optimize` refuse to run without `--live`, print an estimate, and stop above the cap;
- `docs/mlflow-tour.md` names every MLflow-unique feature and every named gap;
- ruff and pyright clean; the full offline suite still passes.

artifact, deleting or altering anything in Braintrust.

## 5. Definition of done

- `just mlflow-sync` dry run, then `--live`, then `--live` again: identical counts, zero new objects on
  the second run, `data/reports/mlflow_manifest.json` committed.
- In the UI: 35 runs with the factorial tags; the Evaluations comparison of the four GLM systems opens on
  `contract_144__q05` and shows A abstaining and B, C, D answering "Actual knowledge"; the Traces tab
  filtered to the redacted twin shows the cap-hit span tree with real timestamps; assessment columns show
  the lawyer's four scores on the 24 packets; the prompt registry lists the eight prompts with aliases;
  the registered model `dealpoint-agent` has `champion` on D@gemini.
- The six deterministic scorers run inside `mlflow.genai.evaluate` and reproduce the stored values.
- `docs/mlflow-tour.md` exists with the nine stops, the "adds" and "gaps" sections, and no number that
  differs from `docs/demo-tour.md` for the same object.
- `gate_m9` passes offline; ruff and pyright clean; full offline suite passes.
- Spend: $0 unless D3/D4 were run; if run, each within its cap and recorded in the spend ledger with
  `milestone_tag: m9`.
