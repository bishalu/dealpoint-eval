# M6 — Model cost/quality Pareto experiment

**Authority:** brief §2.6, §6 acceptance 6. **Spend-gated.** Arm D held fixed (frozen index,
skill, tools, cases); only the model varies.

## Deliverables

1. **Slate** (verify availability and tool-calling on **2 dev cases** at run time; record exact ids
   and prices in `data/reports/pareto_slate.json`): default `anthropic/claude-haiku-4.5` (already
   run in M4 — reuse, do not re-run); cheap cross-family `google/gemini-3.1-flash-lite` (or the
   cheapest Flash-class tool-calling model available); open-weight `deepseek/deepseek-v3.2` (or the
   cheapest reliable open-weight tool-calling model); stronger same-family ceiling
   `anthropic/claude-sonnet-5` — **run last, and only if the remaining envelope covers it on the
   full M4 subset; otherwise on the 12-case judged subset, and the report says so**. Opus is out of
   budget and is listed in the report as "not run (budget)". A model that fails tool calling on the
   2 dev cases is recorded with its failure rate and excluded, not silently swapped.
2. **Sweeps** — arm D on the M4 frozen subset (`test_subset_v1.json`) per model, each preceded by
   `assert_within_cap` with the ledger's measured cost/case; per-model realised cost recorded.
3. **Judging** — the M5 harness on the 12-case judged subset for arm D @ each completed model
   (36 calls per model); calibration packets extended to every judged trace.
4. **Report** — `data/reports/pareto.json` + chart (`pareto.svg`/`png`): per model
   `grounded_accuracy`, `abstain_recall`, `execution_failed`, `cap_hit`, judged quality (mean of
   judges, labelled secondary), median/p90 latency, realised $/case, total cost; the Pareto
   frontier identified deterministically. `judges.json` updated with all variants; README results
   section regenerated.

## Budget scaling (engineer decision, 2026-09-04 — not a spec/brief contradiction)
The whole unattended OpenRouter envelope for M1–M6 is **$4.00** (`MAX_OPENROUTER_SPEND_USD`). Where this spec is smaller than the brief's full-scale design (§2.2, §2.5, §2.6), the scaling below is the engineer's instruction and must be recorded in the report as "budget-scaled", never presented as the full benchmark. Every metered run is sized by `dealpoint.eval.spend.estimate` from measured cost/case in the ledger, and the milestone's own runs must leave headroom for the milestones after it. **Allocation guide (the target): M1+M2 ≤ $0.50, M4 ≤ $1.50, M5 ≤ $0.60, M6 the remainder. Absolute per-milestone limit: double the guide, used sparingly** — exceeding the guide is allowed when it buys measurably better discrimination and the reason is recorded in the report; it is never a REVISE or ESCALATE ground by itself. The $4.00 envelope is the enforced cap and is never exceeded (engineer's instruction, 2026-09-04).

## Factory latitude (engineer's instruction, 2026-09-04)
The sizes in this spec (subset sizes, judge count, calibration-set size, slate order) are
**defaults, not fixed requirements**. The planner, builder and reviewer may change them using
what the build and the ledger reveal (measured cost/case, observed arm disagreement, model
availability) when that buys better discrimination per dollar — subject to: the $4 envelope
and the per-milestone allocation; any subset is fixed **before** its runs and never chosen
from model outputs on those runs; every question keeps ≥ 1 case and counterfactuals stay
in; ≥ 2 judge families; the decision and its reason are written into the milestone's
report and evidence. Such a change is a recorded decision, not a spec deviation, and is
not grounds for REVISE or ESCALATE by itself.

## Cheap workhorse model (engineer's instruction, 2026-09-04)
`z-ai/glm-5.3-flash` on OpenRouter ($0.075/M input, $0.25/M output, tool calling and structured outputs supported; verify at run time and record the price) is the **default model for every dev-loop, smoke, and exploratory metered call** from this milestone on — the builder's own testing included. Haiku is reserved for the runs the spec names it for.
It is a **mandatory Pareto candidate** (the arm-D @ GLM results from M4's replication sweep are reused, not re-run); the open-weight slot may then go to a second open-weight model or be dropped if the envelope is tight.

## Slate and judges (from `specs/milestones/openrouter_sweep_2026-09-04.md`, engineer's instruction 2026-09-04)
Use the ranked candidate slate and the judge trio in that file. The point of M6 is a results table that exposes **real model-switching opportunities** — many cheap models across many families on the same frozen cases — so breadth of the cheap tier beats depth on any one model. Rows 1–7 are the core; 8–10 in order while the allocation holds; the two ceiling anchors last, on the 12-case subset, only with headroom. Reuse every arm-D result already produced (Haiku from M4, GLM from M4's replication). Verify each id on 2 dev cases first; a model that fails tool calling is reported with its failure rate, not swapped silently.

## Metered-call discipline (operator, 2026-09-05)
Every OpenRouter call this milestone makes carries a ledger `milestone_tag` of `m6` and, for
anything that is not a case run, a `purpose` of `probe` with the model id being verified. No call
may go to a model outside the slate or the judge trio (router endpoints such as `openrouter/auto`
or `openrouter/fusion` included): verify availability with the OpenRouter models listing
(no spend) and a single tool-calling probe per candidate. The report lists probe spend separately.
