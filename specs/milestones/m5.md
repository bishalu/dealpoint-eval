# M5 — Calibrated multi-judge evaluation (secondary, clearly labelled)

**Authority:** brief §2.5, Appendix C, §6 acceptance 5. **Spend-gated.** Judge scores are never
presented as objective truth.

## Deliverables

1. **Rubrics frozen first** — `eval/judges/rubrics.md`: four dimensions (reasoning/analysis
   quality; evidence sufficiency; trajectory quality *beyond* deterministic adherence; professional
   answer quality), each with five anchored levels. `rubric_version` = hash, stamped into
   `versions.json` **before any judge call**; a test asserts the hash in every judge result equals
   the frozen one.
2. **Blinding** — judge input = question spec, the trace (tool calls, args, retrieved text),
   finding, and — for evidence sufficiency only — the gold span; arm and model names stripped;
   the same blinded packet is what humans score.
3. **Judges** — three heterogeneous families, none from the M6 candidate slate (Anthropic,
   Google, DeepSeek are candidates): pick the **three cheapest tool-free JSON-capable models from
   three other families** available on OpenRouter at run time (candidates to check: `qwen/…`,
   `openai/…-mini`/`…-nano` class, `x-ai/…-mini` class, `mistralai/…`, `meta-llama/…`); record ids
   and prices; **one call per trace returning all four dimensions** as JSON; judge input trimmed
   to the finding, the trajectory summary (tool, args, section refs, ≤ 600 chars of each retrieved
   text) and the gold span — not full raw traces.
4. **Subset** — **12 cases** (1 per question, drawn from the M4 frozen subset, favouring cases where
   arms A and D disagree — chosen by a deterministic rule written before judging, seeded) written to
   `data/eval/judged_subset.json`. Variants judged in M5: arm A @ Haiku and arm D @ Haiku (24
   traces × 3 judges = 72 calls). M5 realised spend ≤ $0.60.
5. **Calibration package** — `data/eval/calibration/`: blinded packets for every judged trace
   (24 now; M6 adds its variants — the human set is whatever is judged, target ≥ 12, no upper
   bound imposed for its own sake), a scoring form
   (`form.md`) using the identical rubric, and `human_scores.jsonl` schema. `just calibration`
   computes, whenever human scores exist: Spearman ρ and weighted Cohen's κ judge↔human per
   dimension, pairwise judge agreement, and correlation of judged quality with
   `grounded_accuracy`; writes `data/reports/judges.json`. Until human scores exist the report
   carries `"human_calibration": "pending"` and the milestone records the pending input.
6. **Braintrust** — one aggregate (mean-of-judges) score per dimension on the judged subset;
   per-judge scores in metadata.

## Definition of done

- [ ] `gate_m5` offline: blinding strips identities (test); rubric hash check; one-call-four-dims
      parsing with a fake judge; agreement statistics unit-tested on synthetic scores.
- [ ] Spend gate passed; judges run on the 12-case subset for the two M5 variants; `judges.json`
      written with per-dimension aggregates, pairwise judge agreement, correlation with grounded
      accuracy, and `"human_calibration": "pending"`; calibration packets and form written.
- [ ] `specs/mvp/state.json` is NOT edited by the builder; instead the milestone's evidence names
      the pending human input: "score data/eval/calibration/form.md".
- [ ] Full offline suite, `ruff`, `pyright` green.


## Budget scaling (engineer decision, 2026-09-04 — not a spec/brief contradiction)
The whole unattended OpenRouter envelope for M1–M6 is **$4.00** (`MAX_OPENROUTER_SPEND_USD`). Where this spec is smaller than the brief's full-scale design (§2.2, §2.5, §2.6), the scaling below is the engineer's instruction and must be recorded in the report as "budget-scaled", never presented as the full benchmark. Every metered run is sized by `dealpoint.eval.spend.estimate` from measured cost/case in the ledger, and the milestone's own runs must leave headroom for the milestones after it (allocation guide: M1+M2 ≤ $0.50, M4 ≤ $1.50, M5 ≤ $0.60, M6 the remainder).

## Factory latitude (engineer's instruction, 2026-09-04)
The sizes in this spec (subset sizes, judge count, calibration-set size, slate order) are
**defaults, not fixed requirements**. The planner, builder and reviewer may change them using
what the build and the ledger reveal (measured cost/case, observed arm disagreement, model
availability) when that buys better discrimination per dollar — subject to: the $4 envelope
and the per-milestone allocation; any subset is fixed **before** its runs and never chosen
from model outputs on those runs; every question keeps ≥ 1 case and counterfactuals stay
in; ≥ 2 judge families; the decision and its reason are written into the milestone's
report and evidence. Such a change is a recorded decision, not a spec deviation, and is
not grounds for REVISE or ESCALATE by itself.

## Out of scope
Pareto slate runs (M6). No rubric revision after judging without re-running all judges.
