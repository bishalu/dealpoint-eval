## Engineer's directive (verbatim)

Use the attached 24-packet calibration review as diagnostic evidence. The main issue is not raw legal reasoning quality; it is retrieval/control-flow failure plus a couple of substantive interpretation errors.

Implement the following changes:

### 1. Fix defined-term retrieval before changing the model

The system repeatedly finds the correct definitions section but then keeps issuing semantic searches until the cap.

When a query asks about a defined term:

1. Normalize the requested term and party: `Knowledge`, `Knowledge of the Company`, `Company Material Adverse Effect`, `Parent Material Adverse Effect`
2. Run `lookup_defined_term`.
3. If it identifies a section, fetch the full relevant definition from that section.
4. Do not keep searching for paraphrases of the same definition once the section is known.
5. Search should be fallback/recovery, not the primary loop after a definition location is known.

The Nicolet Knowledge runs are the clearest failure: §12.1 was repeatedly identified, but the agent kept searching rather than obtaining enough of §12.1 to resolve the defined term.

Add loop detection for semantically equivalent queries. Queries such as `"Knowledge of the Company" means`, `"Knowledge of the Company" means the actual knowledge of`, `"Knowledge" means actual knowledge` should count as essentially the same retrieval attempt. After 1–2 failed variants, change strategy rather than consuming the cap.

### 2. Retrieve the operative provision, not provisions that merely use the term

For a question about the **definition** of MAE, do not answer from representations that are merely qualified by MAE. The bad example is packet `32fc075d8413`: it answered the forward-looking-standard question from §§4.15, 4.20 and 4.21, even though those provisions merely use `Company Material Adverse Effect`. The answer needed the defined term itself.

Add an evidence hierarchy: 1. exact defined-term text; 2. explicit cross-reference to the definition; 3. directly operative covenant/condition; 4. contextual uses of the term. Do not answer a definition question from tier 4 if tiers 1–2 have not been exhausted.

### 3. Make party qualification first-class

`Company Material Adverse Effect` and `Parent Material Adverse Effect` are different definitions and use different formulations. For the New Home agreement: Company MAE uses `would reasonably be expected to...`; Parent MAE uses `would prevent...` / materially delay. Therefore the current generic question ("What forward-looking standard does the Material Adverse Effect definition use?") is ambiguous. Fix the benchmark/question generator so it specifies **Company Material Adverse Effect** or **Parent Material Adverse Effect**. Do not score an agent against a single answer when the underlying agreement contains both materially different definitions.

### 4. Fix absence/carveout reasoning

Never infer "X is not carved out" from only the introductory language to an exclusion list. To answer whether something is carved out: 1. retrieve the complete exclusion list; 2. distinguish an **expressly named carveout** from possible coverage under broader language; 3. inspect relevant interpretation language such as whether `including` is nonexclusive; 4. state which MAE limb the exclusion applies to.

For the stockholder-litigation question in this agreement, the safe legal distinction is: there is no separately enumerated carveout expressly called `stockholder litigation`; but clause (vii) broadly excludes certain effects arising from the announcement, compliance with, pendency or consummation of the agreement; litigation-related effects may potentially fall within that broader language depending on causation and scope; the carveouts apply only to the business-MAE limb, not automatically to the separate transaction-impairment limb. Therefore packet `790521a3adab` should **not** be treated as a clean exemplar merely because it answered "No." Its evidence did not contain the complete exclusion list, and its rationale was too categorical.

### 5. Require evidence sufficient for the exact proposition

Before emitting a finding, run a support check: "Does the quoted evidence, standing alone, establish the specific answer I am about to give?" To say Knowledge = actual knowledge: quote the actual Knowledge definition. To say an exclusion is absent: retrieve enough of the complete exclusion enumeration to establish absence. To identify `would` vs `could`: quote the actual definition, not another provision using the defined term. If evidence is adjacent but insufficient, retrieve more rather than answer.

### 6. Preserve abstention, but make it occur after intelligent recovery

The abstentions were preferable to hallucinating, but some occurred too early. Recovery sequence: `lookup_defined_term` → fetch identified section / definition range → search exact term in definitions article → search section heading / neighboring defined terms → only then abstain. Do not spend eight calls rephrasing the same search.

### 7. Add explicit stopping rules

Stop retrieval when: the exact operative language has been obtained; the answer options can be distinguished from that language; and no additional contractual qualifier could materially change the answer. Do not continue searching merely to accumulate evidence after the controlling language is already available.

### 8. Improve benchmark construction

Before using these packets as human-calibration ground truth: party-qualify the MAE forward-looking question; decide whether the stockholder-litigation question means (1) "Is stockholder litigation expressly listed as a carveout?" or (2) "Could effects from stockholder litigation be excluded by the MAE definition?"; preserve complete tool results in traces, especially `lookup_defined_term`; ensure gold spans contain the language needed to resolve the legal distinction being tested. The four dimensions (reasoning, evidence, trajectory, professional usability) remain separate.

### 9. Treat these successful Knowledge packets as positive reference cases

`01de6203baeb`, `257db09a639b`, `31aa8adabacf`, `398be705a6ca`, `5b65980d9ad6`. Common pattern: identify the operative Knowledge definition; quote `actual knowledge`; explain that no constructive / reasonable-inquiry standard is included. Use these as answer-quality exemplars, but not necessarily as trajectory exemplars.

### 10. Regression tests to add

Deterministic tests for: defined-term resolution (a definitions-section hit is followed by targeted extraction, not another near-identical semantic search); party qualification (Company MAE and Parent MAE never collapse); definition-versus-use; complete-enumeration requirement for negative carveout answers; broad-versus-express carveout distinction; search-loop detection (semantically equivalent searches trigger a strategy switch before cap exhaustion); evidence entailment (the final cited span establishes the answer).

Primary objective: **increase answer completion by fixing retrieval strategy without lowering the abstention threshold or encouraging unsupported legal conclusions.** Do not optimize merely for fewer CAP_HITs. Optimize for obtaining the controlling provision quickly and making the narrowest conclusion that provision supports.
