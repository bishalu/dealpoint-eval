# M4 — Four-arm experiment on the frozen test set

**Authority:** brief §1.6 (skill), §2.2 (arms), §2.4 (metrics, headline `grounded_accuracy`),
§2.7, §6 (acceptance 3, 7, 8), Appendix B (skill rules and adherence). **Spend-gated.**

## Deliverables

1. **Skill** — `skills/ma-deal-point-review/SKILL.md` (generic procedure, the 8 rules of Appendix
   B, ≤ ~800 tokens) + `playbooks/q01.md … q12.md` (3–5 lines each). `skill_version` = hash of the
   files, written to `versions.json`. Injected as a system-prompt block in **arm D only**; the
   applicable playbook is loaded only for the case's question.
2. **Skill adherence scorer** — each Appendix-B rule as a deterministic trajectory check with an
   *applicable* predicate; `skill_adherence` = satisfied / applicable; computed for **all arms**.
3. **Arms** — configs A/B/C/D exactly as brief §2.2; a test asserts each arm differs from its
   predecessor by exactly one config key.
4. **Frozen discriminative subset** — `data/eval/test_subset_v1.json`, chosen **before any test
   case runs and without looking at any model output**, by deterministic rule: from `test`, 2 cases
   per question (24) favouring the reasoning types where arms should differ — defined-term,
   cross-reference and carve-out questions get their cases first; ties broken by seed — plus 8
   `counterfactual` cases (6 redacted across ≥ 4 questions, 2 out-of-scope). 32 cases. The rule
   and the seed are in the file; a test regenerates it byte-for-byte. Sized so that 4 arms fit the
   M4 allocation at the constant model; if the ledger's measured cost/case says 32 does not fit,
   reduce to 1 case per question + 6 counterfactual (18) by the same rule and record it.
5. **Sweeps** — *(re-sized 2026-09-04 by the operator after M2's estimator projected $3.09 for a
   32-case Haiku sweep — 4× the M4 target — and the ledger showed prompt caching is not taking
   effect: 0 cached tokens on 96 calls.)*
   - **Step 0, before any sweep: diagnose prompt caching.** Run a 2-call probe on
     `anthropic/claude-haiku-4.5` and read `cached_tokens` from the ledger. If the static prefix
     (system prompt + question spec + tool schemas) is below the provider's minimum cacheable
     length for that model, record that fact in the report and move on — **never pad a prompt to
     make it cacheable**. If it is above and still not cached, fix the request shape (block
     placement/order per OpenRouter's Anthropic caching docs) and re-probe. Report the measured
     cost/case before and after.
   - **Headline comparison, constant model `z-ai/glm-5.3-flash`:** arms A–D on the full frozen
     32-case subset (≈ $0.20). A cheap model also makes retrieval and skill effects more visible.
   - **Replication at `anthropic/claude-haiku-4.5`, arms A and D only** (the two ends of the
     chain), on the largest whole-question prefix of the frozen subset that the estimator projects
     at **≤ $1.00** (at least 1 case per question; counterfactuals included). Record N and the
     projection. If caching starts working, N may rise to the full 32 within the same $1.00.
   - Arms B and C at Haiku only if headroom remains under the M4 target after the above.
   - No dev sweep. `assert_within_cap` must pass before each sweep; every projection is recorded.
   **No test run may be used to change any config, prompt, or skill; the skill, arm configs and
   the subset are frozen (hashes recorded) before the first test case runs.**
6. **Report** — `just report` → `data/reports/four_arm.json` (every §2.4 metric per arm, overall and
   per question, plus majority baseline, plus the config diff between adjacent arms, plus
   estimate-vs-realised cost) and `four_arm.md`; README "Results" section regenerated from it with
   the MAUD non-comparability caveat, the objective-vs-judged distinction, and the budget-scaled
   subset stated in the first sentence. Braintrust experiments for each arm, names recorded in
   `braintrust_runs.json`. With 32 cases, report **paired** per-case arm comparisons (which cases
   flipped between arms) — with small N that is the evidence, not aggregate percentages alone.

## Honesty rule
If arm D does not improve `grounded_accuracy` over C, the report says so and shows adherence,
fabrication, abstention, trajectory and efficiency deltas instead; no wording may claim an
improvement the numbers do not support (the reviewer checks the README sentences against the JSON).

## Budget scaling (engineer decision, 2026-09-04 — not a spec/brief contradiction)
The whole unattended OpenRouter envelope for M1–M6 is **$4.00** (`MAX_OPENROUTER_SPEND_USD`). Where this spec is smaller than the brief's full-scale design (§2.2, §2.5, §2.6), the scaling below is the engineer's instruction and must be recorded in the report as "budget-scaled", never presented as the full benchmark. Every metered run is sized by `dealpoint.eval.spend.estimate` from measured cost/case in the ledger, and the milestone's own runs must leave headroom for the milestones after it. **Allocation guide (the target): M1+M2 ≤ $0.50, M4 ≤ $1.50, M5 ≤ $0.60, M6 the remainder. Absolute per-milestone limit: double the guide, used sparingly** — exceeding the guide is allowed when it buys measurably better discrimination and the reason is recorded in the report; it is never a REVISE or ESCALATE ground by itself. The $4.00 envelope is the enforced cap and is never exceeded (engineer's instruction, 2026-09-04).

## Factory latitude (engineer's instruction, 2026-09-04)
The sizes in this spec (subset sizes, judge count, calibration-set size, slate order) are
**defaults, not fixed requirements**. The planner, builder and reviewer may change them using
what the build and the ledger reveal (measured cost/case, observed arm disagreement, model
availability) when that buys better discrimination per dollar — subject to: the $4 envelope
and the per-milestone allocation; any subset is fixed **before** its runs and never chosen
from model outputs on those runs; every question keeps ≥ 1 case and counterfactuals stay
in; ≥ 2 judge families; the decision and its reason are written into the milestone's
report and evidence. Such a change is a recorded decision, not a spec deviation, and is
not grounds for REVISE or ESCALATE by itself.

## Cheap workhorse model (engineer's instruction, 2026-09-04)
`z-ai/glm-5.3-flash` on OpenRouter ($0.075/M input, $0.25/M output, tool calling and structured outputs supported; verify at run time and record the price) is the **default model for every dev-loop, smoke, and exploratory metered call** from this milestone on — the builder's own testing included. Haiku is reserved for the runs the spec names it for.
In M4 it is also a **replication arm set**: after the Haiku sweeps, run arms A–D at `z-ai/glm-5.3-flash` on the same frozen subset (≈ $0.15) and report whether the A→B→C→D deltas replicate across the two models — paired per case. This does not change the constant model of the headline comparison (Haiku).
