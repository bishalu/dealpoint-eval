## Goal

Repair execution failures in the M4 agent-loop evaluation harness. The v1 run was dominated by `EXECUTION_FAILED` outcomes (Haiku arm D 88.9%, GLM arm A 65.6%), masking model reasoning with infrastructure defects. Capture diagnostic evidence (`failure_detail`, `raw_final_text`, `finish_reasons`) on every failure, diagnose via probes, fix the harness (not the benchmark), and re-run the frozen four-arm sweep to get clean v2 results.

## Implementation Summary

### Five harness fixes, all in-scope request-shape repairs:

1. **Evidence capture** (`dealpoint/agent/schema.py`, `_common.py`, `loop.py`, `pipeline.py`, `eval/run.py`):
   - New `ExecutionRecord` fields: `failure_detail` (exception class + first 300 chars of message, with HTTP status and provider error code/type prefixed when present), `raw_final_text` (first 1500 chars of model's final response on schema failures), `finish_reasons` (list of `finish_reason` strings, one per metered call).
   - Helper `describe_exception(exc)` wires exception introspection, guarding all attribute access.
   - Both agent arms and the runner's catch-all exception handler populate these fields.

2. **Tolerant JSON extraction** (`dealpoint/agent/schema.py`, 40 lines):
   - New `extract_json_object(raw: str | None) -> str | None` tries four strategies in order: strict parse; fenced ` ```json ``` ` block; balanced-brace scan respecting string literals and escapes; else `None`.
   - Truncated/unbalanced JSON (no closing brace) still fails—no repair attempted.
   - Wired into `validate_finding_json` before `json.loads`.

3. **Option normalisation** (`dealpoint/agent/schema.py`):
   - New `match_option(answer: str, options: Sequence[str]) -> str | None` canonicalises both sides (curly quotes → ASCII, whitespace collapsed, casefold, strip wrapping quotes) before comparing.
   - On a hit, returns the **exact** option string from `QuestionSpec.options`, so `validate_finding_json` rewrites `finding.answer` to that exact string.
   - No fuzzy matching; `"ABSTAIN"` matches case-insensitively only.

4. **Request shape** (`dealpoint/llm/client.py`, `dealpoint/agent/_common.py`, `config.py`):
   - **`response_format` resolver:** `SUPPORTS_JSON_SCHEMA` dict keyed by model (verified: both Anthropic and GLM return `True`); `response_format_for(model, question)` returns strict schema when supported, falls back to `json_object` otherwise. On a 400 mentioning `response_format`/`json_schema`, retry once with `json_object` and record the downgrade in `failure_detail`.
   - **`MAX_TOKENS_FINAL` doubled:** 600 → **1200** (spec deliverable justified by 21 GLM arm-A v1 failures all hitting the 600 ceiling).
   - **Assistant tool-call message:** when `result.content is None`, emit `"content": ""` instead (provider compatibility).
   - **Retry policy:** exponential backoff with configurable base (`API_RETRY_BASE_DELAY_S`, default ~1.0 s) + jitter; honour `Retry-After` headers. Tests inject smaller base for sub-second run time.
   - **`MAX_TOKENS_TOOL_TURN` unchanged:** left at 300 (see Limitations below); evidence shows it truncates tool turns (27/32 GLM D calls; 7/18 Haiku D calls end at exactly 300 output tokens), but no budget for a re-sweep to validate a higher value.

5. **Tests and gates** (`tests/test_failure_evidence_m4_1.py`, `test_frozen_artifacts_m4_1.py`, `test_report_m4_1.py`, `conftest.py`):
   - Synthetic failures populate `failure_detail`/`raw_final_text`/`finish_reasons`; truncation limits tested.
   - `extract_json_object` unit-tested on fenced blocks, prose-wrapped JSON, truncated strings, brace-in-string, multiple objects.
   - `match_option` tested on case, quotes, whitespace, wrapping punctuation, end-to-end `validate_finding_json`.
   - Frozen-artefact hashes pinned and asserted: `subset_hash`, `skill_version`, sha256 of system_prompt, question specs, skill blocks, ARMS, ARM_ORDER, SCORE_FIELD_NAMES (18-name tuple), MAX_TOOL_CALLS (8).

### Harness structure: frozen benchmark preserved

- **Frozen (byte-identical, hash-asserted):** `data/eval/test_subset_v1.json`, skill files, arm configs, question specs, system prompt, scorers.
- **Changed (implementation only):** client, agent loop, pipeline, schema validation, reporting.
- **Not touched:** frozen subset (32-case GLM, 18-case Haiku), MAX_TOOL_CALLS=8, CAP_HIT logic, skill-adherence definition.

## Known Limitations and Exclusions

1. **Tool-turn truncation not fixed:** MAX_TOKENS_TOOL_TURN left at 300. Evidence shows 27/32 GLM D cases and 7/18 Haiku D cases end tool turns at exactly 300 output tokens, potentially losing tool calls or forcing premature finalisation; identified as a contributing cause to GLM D residual failures but not addressed (budget for only one v2 sweep allocated). Documented in `four_arm.md:46-48` and `README.md:44-46` as a recorded, unfixed limitation.

2. **MAX_TOKENS_FINAL doubled but not raised further:** GLM A/D residual failures (8/32 and 5/32) are due to model verbosity spending the full 1200-token budget on reasoning before JSON output. No cap-raising permitted by spec; these are provider-side decisions, not harness defects.

3. **Majority baseline 0.0% is subset-specific:** by construction (selection rule prefers cases the majority gets wrong). Full MAUD test set baseline is 46.1%; noted in README and report.

4. **Benchmark frozen, no partial re-runs:** v1 run was all-or-nothing (no ability to re-run just failing cases without re-measuring passing ones); v2 treated the same. Probes were diagnostic only on a 2-case sample before committing to full re-run.

5. **Braintrust publishing optional:** Report generated without dependency on any external publishing link; all headline numbers are traceable to `data/reports/four_arm.json` and `data/results/` JSONLs.
