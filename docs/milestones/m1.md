## Goal

Deliver the agent foundation for the dealpoint M&A document QA system: a corpus module with document loading and section-bounded retrieval chunks, a dense index over Qdrant local mode, an LLM client against OpenRouter with native tool calling and spend ledger tracking, and two agent arms (bounded loop with hard cap 8, and a no-loop RAG baseline) that answer MAUD questions using three tools (semantic search, section lookup, term definition) and output findings via a strict JSON schema.

---

## Implementation summary

34 files changed (+3882 -7):

### Corpus module (`dealpoint/corpus/`)
- **`document.py`** (245 lines): Loads canonical documents (original or redacted variants) from M0.1 derived files, exposing text, section map, `get_section(ref)` with normalized reference matching, and `defined_term(term)` regex lookup tolerant of quote style, case, and `Company`-style prefixes. Returns all offsets into canonical text; rank-sorts multiple matches deterministically.
- **`chunks.py`** (130 lines): Section-bounded retrieval chunks, sub-split at ~400 tokens / 50 overlap using the measured `chars_per_token_ratio = 4.845`. Deterministic; chunking parameters hashed into `chunk_version` (8e5e8ba56765). Each chunk carries `{agreement_id, chunk_id, section_ref, start, end, text}`. Front matter (pre-first-section) chunked under `section_ref=""`.
- **`retrievers.py`** (112 lines): `Retriever` Protocol `search(agreement_id, query, k=5) -> list[Chunk]` and `DenseRetriever` over Qdrant local mode (`qdrant-client[fastembed]`, on-disk under `data/index/`), embeddings `BAAI/bge-small-en-v1.5`. Lazy initialization via `LazyRetriever` so offline tests avoid importing qdrant/fastembed. Every search scoped to one document via agreement_id filter.
- **`build_index.py`** (216 lines): One-off CLI `python -m dealpoint.corpus.build_index [--force]` that indexes the 20 selected agreements and 30 redacted variants (~12k chunks total), writes `index_version.txt` and `versions.json`, and measures chunk statistics into `chunk_report.json`.

### LLM client (`dealpoint/llm/`)
- **`client.py`** (312 lines): `OpenRouterClient` using the `openai` SDK against OpenRouter with native tool calling. Every metered call:
  - Passes `extra_body={"usage": {"include": True}}` to capture realized USD.
  - Includes prompt caching setup via `cache_control` on the static prefix (system prompt + question spec + tool schemas).
  - Sets `temperature=0`, with max_tokens bounded per call type (tool turns ≤ 300, final answer ≤ 600).
  - Appends `{ts, milestone_tag, model, calls:1, usd, input_tokens, output_tokens, cached_tokens, cache_write_tokens}` to `data/results/spend_ledger.jsonl`.
  - Retries on `APIConnectionError`, `APITimeoutError`, `RateLimitError`, `InternalServerError` (NOT `BadRequestError`/4xx).
- **`FakeClient`** (80 lines): Offline test client replaying scripted tool calls and final answers; never touches network or ledger.

### Agent module (`dealpoint/agent/`)
- **`schema.py`** (149 lines): Public `Finding` (answer ∈ options ∪ `"ABSTAIN"`; 1–3 evidence `{section_ref, quote}`; rationale ≤ 80 words) and internal `ExecutionRecord` (status ∈ ANSWERED | ABSTAINED | CAP_HIT | EXECUTION_FAILED; trajectory with tool, args, chunk_ids, char_ranges, wall_ms; usage; model/arm/case_id). Strict JSON schema for response_format binding answer to question-specific enums.
- **`tools.py`** (141 lines): Three pure functions over `Document` + `Retriever`:
  - `search_agreement(query, k)`: Dense retrieval returning up to k chunks with section refs and canonical offsets.
  - `get_section(section_ref)`: Cross-reference lookup returning a section's text with offsets.
  - `lookup_defined_term(term)`: Returns the `"Term" means ...` block, fuzzy on case/quotes/prefix.
  - All return `ToolResult` with rendered text (truncated to ≤ 1500 chars, section ref preserved), chunk_ids, and char_ranges. Misses return honest error messages, never silent empty strings or exceptions.
- **`loop.py`** (243 lines): Arm B, the bounded native-tool-calling loop. One agent, hard cap **8 tool calls** → `CAP_HIT`. Structured final output via JSON schema with one schema-validation retry (feeding the error back) → `EXECUTION_FAILED` if still invalid. API errors → 3 retries with exponential backoff → `EXECUTION_FAILED`. Quotes normalized before verbatim checks.
- **`pipeline.py`** (167 lines): Arm A, RAG baseline. No loop: dense top-5 retrieval once, one LLM call, find a finding. Same question spec block, schema, validation/retry rules, and execution record shape as arm B, isolating agency.
- **`prompts.py`** (58 lines): Question spec block shown in both arms (MAUD question, gloss, exact option strings, output schema, tool descriptions). No skill content here (scheduled for M4).
- **`run.py`** (131 lines): CLI `python -m dealpoint.agent.run --case <case_id> --arm A|B --model <id> [--fake]` resolving the case from dev/test/counterfactual JSONL, loading the document (redacted variant or base), running arm A or B, printing finding + record as JSON. Exit code 1 on `EXECUTION_FAILED`.
- **`_common.py`** (79 lines): Shared retry wrapper (`call_with_retries` with backoff ≤ 2.0s, excluding 4xx errors) and execution record builder.

### Configuration and data
- **`dealpoint/config.py`**: Added M1 chunking params (CHUNK_TARGET_CHARS=1900, CHUNK_OVERLAP_CHARS=240, measured at 4.845 chars/token), retriever settings (BAAI/bge-small-en-v1.5, Qdrant collection name, k=5), agent caps (MAX_TOOL_CALLS=8, MAX_TOKENS_TOOL_TURN=300, MAX_TOKENS_FINAL=600, LLM_TEMPERATURE=0), retry limits (API_MAX_RETRIES=3, SCHEMA_MAX_RETRIES=1), OpenRouter base URL, and spend ledger path.
- **`data/reports/`**: `index_version.txt` (e2b4a2b97561), `versions.json` (parser/dataset/chunk/index versions, embedding model, document/chunk counts), `chunk_report.json` (measured chars/tokens statistics over 500 sampled chunks).
- **`data/results/spend_ledger.jsonl`**: 68 rows from milestone runs, all tagged `"m1"`, each with model, input/output tokens, usd (key for unattended spend guards), timestamp.

### Tests (130 offline, 61 gate_m1 with live model smoke)
- `test_corpus_document.py`: Document loading, section normalization, defined-term matching on synthetic and real contracts (Material Adverse Effect resolves).
- `test_chunks.py`: Chunk boundaries, section-boundedness, determinism, offset round-tripping.
- `test_agent_schema.py`: Finding validation, evidence counts, rationale word limits, question-bound enum checks.
- `test_agent_tools.py`: Tool dispatch, error handling, section ref preservation, truncation logic.
- `test_agent_loop.py`: Loop termination, cap hit detection, schema retry, API error retry, final status assignment.
- `test_llm_client.py`: OpenRouter payload structure, FakeClient scripting, cache_control headers, spend ledger rows.
- `test_prompts.py`: Question spec block integrity, absence of M4 skill content (with gate pins so the leak cannot return).
- `test_smoke_m1.py` (gate_m1+needs_model): 2 dev cases (one direct MAUD question, one defined-term lookup), arm B, Haiku, all findings ANSWERED with verbatim quotes from the canonical text, 8 ledger rows totalling $0.0437 ≤ $0.15 ceiling.
- `test_index_sanity.py`: Rebuilt dense index (12,312 points, 50 documents) passes a retrieval sanity check: at least one of 5 sampled dev cases returns a chunk overlapping the gold span.
- `test_verbatim.py`: Quote verbatim-matching logic under canonical normalization.

## Known limitations and exclusions

1. **Budget-scaled from brief design:** The full specification (brief §2.2, §2.5, §2.6) contemplates larger proof runs and multi-arm tournament. M1 scope reduced to 2 dev smoke cases per allocation guidance ($0.50 for M1+M2); realised spend $0.3754 leaves ~$0.094 for M2 Braintrust runs.
2. **Prompt caching:** Inert at M1's ~5k-token prefix size (OpenRouter threshold ~5–10k). No test asserts engagement; included per spec for scalability.
3. **No skill content:** System prompt and question blocks intentionally generic (M4 adds question-specific rules); reviewable absence by test.
4. **Qdrant single-writer:** Local mode under `data/index/` is not concurrent-safe; M3/M4 parallel sweeps must not share the index database.
5. **Out of scope:** Scorers, Braintrust integration, tournament, arms C/D, multi-turn dialogue.
