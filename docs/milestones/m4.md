# M4: four-arm experiment on the frozen test set

## Goal

Evaluate a four-arm configuration experiment (A → B → C → D, each adding one feature) on a frozen, discriminative subset of MAUD's test set to measure the independent contribution of retrieval, agent loop, and skill-guided instruction. The primary metric is `grounded_accuracy` (objective, Python-deterministic); secondary metrics include skill adherence, fabrication, abstention, and token efficiency. Results are budget-scaled to a 32-case subset (18 cases at Haiku) due to spend constraints, not the full 167-case test set.

## Implementation summary

**Frozen surfaces** (before any test run):
- **Skill**: `skills/ma-deal-point-review/SKILL.md` (8 procedural rules, ~480 tokens) + playbooks `q01.md`–`q12.md` (3–5 lines each). Skill version hash `f8d255cc169b` stamped to `data/reports/versions.json`.
- **Arms A–D**: Configs diffing by exactly one key (brief §2.2): A uses pipeline loop + dense retriever; B adds agent loop; C upgrades to hybrid_rrf retriever (fetch_k=20, rrf_k=60); D injects the skill as system-prompt block (arm D only).
- **Frozen test subset**: `data/eval/test_subset_v1.json`: 32 cases (18 tranche_1, 14 tranche_2) chosen by deterministic rule before any model output: 2 test cases per question (24) favouring reasoning types where arms differ (defined-term, cross-ref, carve-out), plus 6 redacted counterfactuals across ≥4 questions and 2 out-of-scope cases. Dataset version `81ed82cd7552`, subset hash `be2e96433b14`, seed 42. Regenerable byte-for-byte; no gold_answer == majority_answer cases in the subset.

**Skill-adherence scorer**: Deterministic trajectory check for each of Appendix B's 8 rules with an `applicable` predicate; scored for all arms. Trajectories sampled from runs carry the per-rule satisfied/applicable counts.

**Sweeps** (metered, on git SHA 4d2e361, index e2b4a2b97561):
1. **Caching probe** (diagnostic, 13 Haiku calls): Static prefix measures 511–609 tokens (system + spec + tools), below Anthropic's 2048-token minimum. Cached tokens observed on zero calls. Decision: do not pad the prompt (spec forbids it); caching does not apply to this model at this prefix size.
2. **Headline comparison** (z-ai/glm-5.3-flash): Arms A–D on full 32-case frozen subset. GLM chosen as primary because caching is not available at Haiku, making retrieval and skill effects visible; also cost-effective ($0.075/M input, $0.25/M output).
3. **Replication** (anthropic/claude-haiku-4.5): Arms A and D only, on tranche_1 (18 cases, the largest whole-question prefix). Haiku reserved for replication per spec.
4. **Dev smoke** (pre-sweep sanity): 2 legs (arms C and D at GLM, 3 cases each) to validate agent-loop and skill injection.

Spend guard in place: runner reads `DEALPOINT_MILESTONE_ABSOLUTE_USD` and `DEALPOINT_MILESTONE_SPEND_START_USD` before any sweep >10 cases; refuses if (realized − start) + estimate > absolute. M4 target ≤ $1.50, absolute ≤ $3.00 within $4.00 envelope.

**Report generation**: `just report` → `data/reports/four_arm.json` (6 sweep legs, all §2.4 metrics per arm overall and per question) + `four_arm.md` (markdown tables, per-question detail, paired per-case flips, majority baseline, estimate-vs-realised cost) + README "Results" section (auto-regenerated with MAUD non-comparability caveat, objective-vs-judged distinction, budget-scaled subset noted). Braintrust experiments named and recorded in `data/reports/braintrust_runs.json`.

**Honesty rule**: If arm D does not improve grounded_accuracy over C, the report states so and shows adherence/fabrication/abstention/trajectory/efficiency deltas instead; no wording claims unsupported improvement. At GLM, arm D regresses: 64.7% (arm C) → 61.5% (arm D), delta −3.2%, improves=false. Haiku A–D comparison marked not comparable due to denominator: 9 scored vs 2 scored, 1 in common.

## Known limitations and exclusions

1. **Prompt caching not available**: Static prefix (system + spec + tool schemas) is 511–609 tokens, below Anthropic's 2048-token minimum for the Haiku model class. Caching was probed and confirmed at 0 cached tokens on all 13 probe calls and all 96 prior ledger rows. Spec forbids padding to reach the minimum; no workaround applied.

2. **High EXECUTION_FAILED rates**: At Haiku, arm D shows 88.9% execution_failed (mostly api_error), arm A 5.6%. At GLM, arm A 65.6% (schema_invalid_after_retry), others 12.5–34.4%. M4.1 later traced most of these to the harness (missing failure evidence, strict JSON parsing, a 600-token final-answer cap) and re-ran the sweep; see `m4_1.md`.

3. **Arms B and C not run at Haiku**: Budget constraint. GLM headlines + Haiku A/D replication left no headroom for B/C without exceeding the $1.50 target; estimated cost was ~$1.57 at Haiku for all four arms. Replication shows only the endpoints (A→D delta).

4. **Subset is budget-scaled, not full brief design**: 32-case frozen subset (18 at Haiku) vs. full 167-case test set in brief §2.5. Spend allocation: M1+M2 ≤ $0.50, M4 ≤ $1.50, M5 ≤ $0.60, M6 remainder of $4.00 envelope. Realized M4 spend: $0.751879 (52% of target, under by $0.75). Every reported result is labeled "budget-scaled" in README.md and four_arm.md:1.

5. **Arm D does not improve over arm C at the headline model**: At GLM (primary), arm D regresses: 64.7% → 61.5%, delta −3.2%. Report shows this honestly; skill injection does not lift grounded_accuracy on this model/subset. Possible causes (not investigated, out of scope): arm D's skill guidance may interfere with GLM's retrieval-answer alignment, or the defined-term/cross-ref/carve-out questions where skill should help are too sparse in the 32-case subset.

6. **No model-as-judge, no human review**: All metrics are deterministic Python over expert labels from the spec. No model-based evaluation of answer quality, relevance, or reasoning trajectory. This is by design (brief §2.4) and noted in README.md:5.
