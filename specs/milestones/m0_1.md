# M0.1 — Data foundation repair: parser coverage, selection bias, abstention set

**Authority:** `specs/grilled-product-brief.md` (§2.1, §3.4, §5, §7 M0). This spec corrects two
benchmark-integrity defects found on inspection of M0 (commit `1fcc2e7`). It is a correction of
M0, so its gate is the existing `gate_m0` marker plus the new tests named below.

## Problem A — section parser coverage and selection bias

The M0 parser (`dealpoint/data/sections.py`) yields ≥ 0.8 "coverage" on only 60/152 agreements
(median 0.71; 36 agreements ≈ 0). Causes observed: zero-padded `Section 1.01` headings; `Article I.`
with a trailing period and mixed case; a 20,000-char section ceiling that penalises legitimate
long Definitions sections; exhibits/post-signature material counted as body. Because eligibility
required ≥ 0.8, the selected 20 agreements are biased toward one drafting style.

### Required changes

1. **Heading forms.** Recognise, inline over canonical text: `Section N.N`, `SECTION N.N`,
   `Section N.NN` (zero-padded), `N.N Title`, `N.NN. Title`, `§ N.N`, `ARTICLE I` / `Article I.` /
   `ARTICLE 1` (roman or arabic, optional trailing period, any case). Keep the table-of-contents
   run detection and the "numbering must advance" cross-reference filter, and make advancing work
   for zero-padded numbering (`1.01 → 1.02`).
2. **Sections ≠ chunks.** A *canonical legal section* is whatever the heading structure delimits,
   at any length. Retrieval sub-chunks are a later milestone's concern and must not influence the
   section map. Remove the length ceiling from the coverage definition.
3. **Structural coverage metric.** `structural_coverage` = fraction of *body* characters that fall
   inside a recognised, advancing section, where *body* runs from the first Article/Section heading
   after the TOC to the start of the signature block (first `IN WITNESS WHEREOF`, else the last
   heading). Report separately, per agreement: `n_sections`, `max_section_chars`,
   `giant_single_section` (true when one section holds > 40% of body), and
   `gold_span_section_rate` (fraction of this agreement's aligned gold spans for the 12 questions
   whose midpoint lies inside a recognised section, excluding a giant one). Do not tune these
   definitions to hit a number.
4. **Recompute from raw source for all 152** and write `data/derived/sections/{id}.json` with the
   fields above plus `parser_version`.
5. **Stale-state guard.** `parser_version` = a short hash of `sections.py`'s source. Every derived
   sections file records it; `select.py` and `cases.py` must refuse to run on derived files whose
   `parser_version` differs from the current one (raise with a message naming `just data`), and
   `cli.py data` must rebuild them instead of reusing them. A `gate_m0` test asserts the guard
   fires on a mismatched file.
6. **Eligibility and re-selection.** Eligible = `structural_coverage ≥ 0.8` and not
   `giant_single_section` and ≥ 10/12 questions with a usable aligned gold span. Target ≥ ~120/152
   eligible *if the corrected metric supports it* — report the real number either way. Re-run the
   seeded selection (`SEED=42`) over the new eligible set; the 20 may change. Regenerate
   `data/eval/{dev,test,counterfactual}.jsonl`, `selection.json`, `excluded.json`, and derived
   metadata. `selection.json` must record every rejection reason and the `parser_version`.
7. **Report.** `data/reports/m0_1_parser_report.json` with: per-agreement structural metrics, the
   eligible count, the distribution of `structural_coverage`, giant-section failures (ids), and the
   corpus-wide `gold_span_section_rate`. Also write `data/reports/parser_version.txt` and
   `data/reports/dataset_version.txt` (sha256 over the three case files, first 12 hex).

## Problem B — fake abstention difficulty

The 10 out-of-scope questions in `dealpoint/data/questions.py` are jokes. Replace them with exactly
these, expected answer `ABSTAIN`:

1. What percentage of the Target's employees have executed invention-assignment agreements?
2. What is the Target's current cyber-insurance deductible?
3. Which ERP system will the combined company use after closing?
4. What annualized cost synergies are expected during the first twelve months after closing?
5. What percentage of the Target's revenue comes from customer contracts containing change-of-control termination rights?
6. What is the Target's accrued employee PTO liability as of signing?
7. What is the weighted-average remaining term of the Target's office leases?
8. What is the expected post-closing retention-bonus pool for non-executive employees?
9. What percentage of the Target's source code has been reviewed for open-source license compliance?
10. Which jurisdiction governs the Target's ten largest customer contracts?

**Collision check (deterministic):** for each out-of-scope question and each selected *test*
agreement, search the canonical text for that question's key terms (a small hand-written
term list per question stored beside it, e.g. `["cyber", "deductible"]`). Write the result to
`data/reports/m0_1_oos_collisions.json`. If an agreement's text plausibly establishes the asked fact
(all key terms co-occur within 400 characters), do not use that pairing; if a question collides on
every test agreement, replace it with one of these spares, in order, and record the substitution:
(a) What is the Target's average customer contract renewal rate over the last three fiscal years?
(b) How many of the Target's patents expire within five years of closing?
(c) What is the Target's headcount attrition rate for the twelve months before signing?

      and `Article I.`; the TOC and cross-reference filters still pass their existing tests.
- [ ] `structural_coverage`, `giant_single_section`, `gold_span_section_rate` implemented as defined
      and tested on synthetic documents.

- [ ] `data/reports/m0_1_parser_report.json` exists; eligible count reported; a test asserts eligible
      ≥ 100 (a floor, not the target — the target is reported, not gated) and corpus
      `gold_span_section_rate ≥ 0.9`.
- [ ] Selection re-run; 20 agreements, 5 dev / 15 test; all M0 alignment gates still pass
      (fragment-level ≥ 0.95, case-level any ≥ 0.95, all ≥ 0.90).
- [ ] `OUT_OF_SCOPE_QUESTIONS` equals the fixed list (or documented spare substitutions);
      counterfactual set has 30 redacted + 10 out-of-scope cases; collision report written.
- [ ] Byte-for-byte deterministic rebuild test passes against the newly committed case files;
      `python -m dealpoint.cli data` run twice changes no committed byte.
- [ ] `uv run pytest -m "not needs_network and not needs_model" -q`, `uv run ruff check .`,
      `uv run pyright` all exit 0.
