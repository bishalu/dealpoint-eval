# M5: calibrated multi-judge evaluation

## Goal

Add model-judged secondary scores on merger-agreement Q&A traces to calibrate against human reasoning and measure judge agreement. Score results are secondary (never presented as objective truth) and budget-scaled per engineer instruction 2026-09-04, the full brief's scale (40 cases, 6 variants, 720 calls) is deferred to future envelopes.

## Implementation summary

M5 delivered a complete judge-based evaluation pipeline:

- **Rubrics frozen first**: Four dimensions (reasoning/analysis quality; evidence sufficiency; trajectory quality; professional answer quality), each 5 anchored levels in `eval/judges/rubrics.md`. Hash `cfda9f8cc401` frozen in `versions.json` before any judge call; every judge result carries it and is asserted in tests.
- **Blinding**: Judge input stripped of arm and model identity, reduced to question, trace (tool calls, args, retrieved text ≤600 chars), finding, and gold span (evidence dimension only). Same blinded packet format used for both judges and human calibration form (`data/eval/calibration/form.md`).
- **Judge trio**: Three heterogeneous families (Mistral, NVIDIA, ByteDance) from outside the M6 candidate slate, one call per trace returning all four dimensions as JSON. No tools. Temperature 0, structured output (json_object).
- **Judged subset**: 18 cases from M4 frozen subset (test_subset_v1 tranche_1, 12 test cases + 4 redacted + 2 out-of-scope) drawn by deterministic seeded rule (disagreement favoring, seed 42) BEFORE any judge call. Three variants: A@Haiku, D@Haiku, D@GLM; 54 traces × 3 judges = 162 calls, all successful.
- **Calibration package**: `data/eval/calibration/` holds 54 blinded packets (packets.jsonl, packets.md), the rubric-identical scoring form (form.md), empty human_scores.jsonl with schema, and variant_key.json (not to be opened until scoring complete). Pending human input recorded as "score data/eval/calibration/form.md".
- **Braintrust integration**: Three judged-* experiments (one per variant), mean-of-judges normalised (mean-1)/4 per dimension, per-judge scores in metadata only. No test-set scores logged.
- **Agreement & correlation**: Pairwise Spearman ρ and quadratic-weighted kappa per judge pair and dimension; Pearson and Spearman correlation with grounded_accuracy (n=25, under-powered per statistics notes).

## Known limitations and exclusions

1. **Budget-scaled**: 18 cases × 3 variants × 3 judges = 162 calls (brief called for 40 × 6 × 3 = 720). Every number is scaled and recorded as such in judges.json.brief_differences.

2. **Blinding not perfect**: Trajectory shape (arm A = single-shot, arm D = agent loop) can leak identity to knowledgeable readers; empty option lists hint out-of-scope probes.

3. **Human calibration pending**: The form is ready and packets are scored by judges; human scoring (target ≥12, no upper bound) must be completed before judge↔human agreement can be computed. Entry point: `score data/eval/calibration/form.md`.

4. **Correlation under-powered**: n=25 cases < 30-case recommendation; Spearman ρ and Pearson r are valid but low-power statistics.

5. **Judge families changed**: Brief's illustrative example (GPT + Grok + Qwen) conflicts with brief's own rule (no families in candidate slate), because the candidate slate evolved after the brief. Engineer's trio (Mistral, NVIDIA, ByteDance) honors the rule; the brief's example does not.

6. **No rubric revision after judging**: All 162 calls are frozen. Any rubric change would require re-running all judges.
